先日、[NotionをAIの「共有の脳」にするという発表]({% post_url 2026-11-09-notion-shared-ai-memory %})について書きました。私はChatGPTとClaudeを使っていて、自分の考え方をまとめ、どちらと話すときにも使えるようにしたいと思っていました。

残したいのは、プロフィールだけではありません。開発するときに何を大切にするか、どういうUIを使いやすいと感じるか、判断に迷ったら何を優先するか。そういう基準もAIに渡せる形にしたいです。

そこで、質問に答えると自分の言葉がMarkdownにまとまる、対話式のPythonスクリプトを用意しました。今回はその使い方を紹介します。

## 「使いやすくして」の前提を、少し具体的にしたい

AIに「使いやすいUIにして」と頼むとき、自分の中にもまだ言語化できていない好みや判断があると思います。

たとえば、操作回数を減らしたいのか、一つひとつの操作をわかりやすくしたいのか。初めて使う人を重視するのか、繰り返し使う人の速さを重視するのか。どちらを選ぶかで、作る画面は変わります。

「シンプルが好き」と一言残すだけでは、情報を隠しすぎるかもしれません。理由や具体例、例外まで整理しておくと、AIに提案してもらうときの前提にできそうです。

## スクリプトで聞くのは15問

質問は、価値観から開発時の確認方法まで、次の範囲を扱います。

| テーマ | 質問の例 |
| --- | --- |
| 活動の目的 | 誰のために、どんなものを作りたいか |
| 価値観と理由 | 大切にしたいことと、そう考えるようになった経験 |
| 優先順位と例外 | 見た目・使いやすさ・速さ・保守性がぶつかったらどう選ぶか |
| UI・UX | よかった体験、困った体験、初めて使う人への配慮 |
| アクセシビリティ | 文字、色、キーボード操作、動きで配慮したいこと |
| 開発と確認 | 何を守り、何を確かめたら完成と判断するか |
| AIとの協働 | 任せたい範囲、相談してほしい判断、意見の伝え方 |
| 現状と見直し | 今のプロジェクト、迷っていること、考えを見直す条件 |

決まっていないことは、飛ばしても大丈夫です。「まだ迷っている」と書くこともできます。

スクリプトは回答をAIで分析しません。本人が書いた言葉を項目ごとに配置し、未回答は未決定として残します。回答から性格や価値観を勝手に推測する処理も入れていません。

## ダウンロードと実行方法

必要なのはPython 3.10以上です。追加のライブラリやAPIキーは使いません。

- [スクリプト一式をダウンロード（ZIP）]({{ '/assets/downloads/ai-context-setup.zip' | relative_url }})
- [Pythonスクリプトを見る]({{ '/assets/downloads/ai-context-setup/setup_context.py' | relative_url }})
- [使い方のREADMEを見る]({{ '/assets/downloads/ai-context-setup/README.md' | relative_url }})

ZIPを展開し、ターミナルで展開先のフォルダへ移動して、次のコマンドを実行します。

```sh
python3 setup_context.py --output my-ai-context
```

Windowsなど、Pythonを`python`で起動する環境では、先頭の`python3`を`python`に置き換えてください。

質問が表示されたら、一問ずつ自由文で答えます。たとえば次のような流れです。回答は説明用の架空の例です。

```text
[2/15 考え方] ものづくりで大切にしたいことを3つ挙げるなら？
> 初めてでも迷わないこと、操作の結果がわかること、あとから直しやすいこと

[3/15 考え方] その価値観を大切にするようになった経験や理由は？
> 保存できたかわからず、同じ操作を何度も繰り返したことがあるため
```

外部への送信やGitHubへの登録は行わず、指定したフォルダにファイルを作ります。

## 回答すると、何ができる？

出力先には、次のファイルができます。

```text
my-ai-context/
├── README.md
├── profile.md
├── principles.md
├── ui-ux.md
├── development.md
├── collaboration.md
├── project.md
├── review.md
├── AGENTS.md
├── CLAUDE.md
└── .context-state.json
```

`principles.md`には価値観や優先順位、`ui-ux.md`には操作体験についての回答が入ります。`AGENTS.md`と`CLAUDE.md`には、関連文書を参照すること、推測を本人の方針として保存しないことなど、AI向けのルールを入れています。

`.context-state.json`は再編集用の回答データです。このファイルにも本人の回答が含まれるので、共有するときはMarkdownとあわせて内容を確認してください。

## 途中でやめたり、あとから直したりできる

一度に全部答える必要はありません。

| 入力 | 動作 |
| --- | --- |
| 空のままEnter | 前の回答を維持。初回なら未回答のまま進む |
| `:quit` | ここまで保存して終了 |
| `:clear` | その質問の回答を削除 |

同じ出力先を指定して再実行すると、前の回答を表示しながら最初の質問から見直せます。

生成したMarkdownを手動で編集した場合は、その内容を上書きしないように停止します。その場合は別の出力先へ生成し、差分を見て必要な部分を統合してください。

## ChatGPT・Claudeで使うには

まずは出力された文書を自分で読み、必要なものをチャットに添付して相談できます。たとえば、こんな頼み方です。

```text
添付したprinciples.mdとui-ux.mdを、開発の相談の前提として読んでください。
今回は、初めて使う人向けの設定画面を考えています。
判断基準に照らして、案とトレードオフを説明してください。
前提が足りないところは、私に質問してください。
```

GitHubの専用の非公開リポジトリに置き、対応するAIの連携や開発環境から参照する方法も考えられます。読み書きできる範囲は環境によるので、最初は「読んだ文書を報告してもらう」「更新は候補を出してもらう」形が確認しやすそうです。

`AGENTS.md`や`CLAUDE.md`を置けば、通常のChatGPTやClaudeのチャットに自動適用されるわけではありません。専用リポジトリの情報を別の開発プロジェクトでも使うなら、その場所と読む対象をAIに伝える必要があります。

## これはハーネスエンジニアリング？

自分の価値観を文書にする部分は、AIに渡す情報を整えるコンテキストエンジニアリングに近いと考えています。Anthropicも、AIに必要な情報を選び、管理することの重要性を説明しています。[Anthropicの解説](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

そこから、AIが関連文書を読み、作業を進め、結果を検証し、学んだことを更新する仕組みまで整えると、ハーネスエンジニアリングの一部になります。OpenAIの解説でも、エージェントが理解できるリポジトリの知識や、検証・改善の仕組みが扱われています。[OpenAIの解説](https://openai.com/index/harness-engineering/)

今回のスクリプトが作るのは、その土台となる文書です。AIへの接続や開発の実行、テストの自動化までは含めていません。

## 自分の好みと、ユーザーにとっての使いやすさは分けたい

価値観を残すときに大切にしたいのは、それを唯一の正解にしないことです。

自分が好きなUIでも、対象ユーザーに合うとは限りません。自分の判断基準は提案の出発点にしつつ、実際の操作や反応を見て変えられるようにしておきたいです。

また、一つのプロジェクトだけの制約を、すべての開発に共通する価値観として残さないことも必要です。そのため、今回の質問には例外や見直し条件を入れています。

私はChatGPTとClaudeのどちらを使うときにも、自分の考え方を持っていけるようにしたいと思っています。まずは質問に答えてみて、出てきた文書を読みながら、「これは本当に自分が大切にしたいことか」を考えるところから始めたいです。
